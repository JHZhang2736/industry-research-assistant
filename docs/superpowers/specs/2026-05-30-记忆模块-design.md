# 记忆模块重构设计（mem0 长期记忆 + 自研工作记忆压缩）

> 日期：2026-05-30
> 分支：`worktree-feat+memory-mem0`
> 定位：课程/作品项目为主 —— 目标是演示一套技术上讲得通、架构干净、行为可见的记忆模块。

---

## 一、背景与问题

项目里已存在一个**半成品**长期记忆模块，但状态是"只读不写、与旗舰功能脱节、偏好学习是空壳"：

- `memory_service.py`（`MemoryService`）实现了对话总结 → 向量化写 Milvus → 召回 → 拼上下文，但：
  - **写路径不自动**：`create_memory` 只在手动 API `/memories/create` 被调用；`should_compress`（token 阈值 10000）写好了却无人调用。对话过程中记忆**永不自动生成**。
  - **DeepResearch V2 完全没用记忆**：核心卖点与记忆脱节。
  - **"用户偏好学习"是空壳**：`summarize_conversation` 抽了 `user_preferences`，但向量化只存 summary/insight/topics，preference 没落库、无法召回。
  - 无去重/合并/遗忘；召回只有纯向量检索。
- Chat 侧 `chat_service.py` 已接入读路径（`build_memory_context` 注入 prompt），但同样不写。

**信源可信度现状**（决定了为何不做信源记忆）：`scout.py` 的 `credibility_score` 是**纯 LLM 按一张静态评分表当场自评**，无真实信誉库、无历史追踪、跨研究不一致。本次**不做**信源信誉记忆。

## 二、目标与范围

重新设计一套更强的记忆架构，最终落三块能力：

| 块 | 类型 | 存储/实现 | scope |
|---|---|---|---|
| **偏好层** | 长期记忆（过程记忆） | mem0 | `user_id` |
| **方法规范层** | 长期记忆（过程记忆，来自 Critic 反馈） | mem0 | `industry`（行业级） |
| **上下文滚动压缩** | 工作记忆（短期） | 自研 | 单会话 |

**明确不做（YAGNI / future work）：**
- 信源信誉记忆（LLM 自评现状，记忆收益已论证为弱且需自研聚合表）。
- 领域事实/数据沉淀的完整 TTL 复用（时效治理重、ROI 弱）。
- 研究情景记忆（"记得上次研究过什么"）—— 需跨会话用户活跃才显效，作品里偏演示性，本次砍掉。
- DeepResearch 侧的上下文压缩（仅做 Chat，研究侧列为 future work）。

## 三、架构总览

```
长期记忆 (mem0 + Milvus)
   ├── 偏好层       scope=user_id      写:Chat/研究后  读:Planner / Writer / Chat
   └── 方法规范层   scope=industry     写:研究COMPLETED 读:Planner（生成大纲前，规避历史教训）

工作记忆 (自研)
   └── 上下文滚动压缩  阈值触发 + 完整保留最近 K 轮  → Chat prompt 组装
                       （rolling summary 持久化到 ChatSession）

清理 (纯 mem0)
   ✗ 删 LongTermMemory 表/模型、旧 memory_service 全部遗留逻辑
   ✗ 删 User / ChatSession 的 memories relationship + 一次 Alembic 迁移
   ↻ memory_router 改为读 mem0.get_all(user_id) 列出"我的记忆"（保留接口、换数据源）
```

### 技术选型（已定）

- **mem0**：自托管开源版（`from mem0 import Memory`，不用云端 API key），**锁定版本**规避 API 漂移。
- **LLM 抽取 + embedder**：均复用 **DashScope**（OpenAI 兼容）。embedder = `text-embedding-v4`，维度 **1024**（与现有 Milvus 集合一致）。
- **向量库**：复用现有 **Milvus**，mem0 用独立集合 `mem0_memories`（dim 1024）。
- **行业判定**：`classify_industry(query)` 复用 `config/industry_config` 关键词；落不到 4 个预置行业归 `"general"`。

## 四、组件设计

### 4.1 `service/memory_engine.py`（新，单例懒加载）

仿现有 `milvus` 懒加载风格，首次访问才初始化 mem0。

```python
class MemoryEngine:
    """mem0 封装 —— 偏好层(用户级) + 方法规范层(行业级)"""

    # ── 偏好层（scope = user_id）─────────────────────────────
    def remember_preferences(self, user_id: str, messages: list) -> None:
        """mem0.add(messages, user_id=user_id, metadata={"type":"preference"})
        靠 mem0 自动抽取 / 去重 / 更新。后台调用、best-effort。"""

    def recall_preferences(self, user_id: str, query: str, k: int = 5) -> str:
        """search → 过滤 type=preference → 拼成 "[用户偏好]" 段。失败返回 ""。"""

    # ── 方法规范层（scope = "sop::{industry}"）───────────────
    def remember_lessons(self, industry: str, critic_feedback: list[dict],
                         quality_score: float) -> None:
        """从 CriticFeedback(issue_type/severity/suggestion) 提炼"研究教训"文本，
        逐条 add(user_id=f"sop::{industry}", metadata={"type":"sop","issue_type":...})。
        mem0 自动合并 → 自然 curation。"""

    def recall_lessons(self, industry: str, query: str, k: int = 5,
                       min_recurrence: int = 2) -> str:
        """search → 过滤 type=sop 且复现≥min_recurrence → 拼成 "[过往研究教训]" 段。"""
```

**scope 约定**：偏好层 `user_id=<系统用户ID>`；方法规范层 `user_id=f"sop::{industry}"`（借 mem0 的 user_id 维度承载行业级 scope）。

### 4.2 `service/context_compressor.py`（新，自研工作记忆压缩）

```python
class ContextCompressor:
    KEEP_RECENT_TURNS  = 4       # 最近 N 轮完整保留（可配置）
    COMPRESS_THRESHOLD = 6000    # 历史 token 超此值才触发（可配置）

    def build_history(self, session, messages: list) -> str:
        """组装 Chat 的 history 段：
        1. 估算 history token；未超阈值 → 全部原文返回，不压缩。
        2. 超阈值 → 切分：
             recent = 最近 KEEP_RECENT_TURNS 轮  → 原文完整保留（零损耗）
             older  = 更早历史                   → LLM 压成"对话摘要"
        3. 返回 = [对话摘要] + [recent 原文]
        """
```

**增量压缩（不每轮重压）**：滚动摘要持久化到 `ChatSession` 新增字段：
- `context_summary: Text` —— 已压缩历史的摘要。
- `summarized_up_to: Integer` —— 已压缩到第几条消息（游标）。

下次触发时只把"新产生的、超出 recent 窗口的旧轮次"并进已有 `context_summary`，而非从头重压。

**与 mem0 协同（可选）**：触发压缩那一刻，把被压掉的旧段落顺手喂 `remember_preferences` —— 一次摘要，压缩与抽长期偏好都做掉。

## 七、错误处理与降级（关键原则：记忆永不拖垮主流程）

- `MemoryEngine` 所有方法 `try/except` 全包：**读失败返回 `""`，写失败静默 no-op**。
- 读路径加短超时；mem0 / Milvus 挂掉 → 研究/对话照常跑，只是没记忆增强。
- 所有写走 `BackgroundTask`，不进主响应链路。
- `ContextCompressor` 压缩失败 → 退化为"截断旧历史 + 保留最近 K 轮"，不抛错。
- mem0 **锁版本号**（写进 `requirements.txt`）。

## 八、测试策略

- **单元（mock `mem0.Memory`）**：
  - `recall_preferences` / `recall_lessons` 的拼接格式与空结果处理。
  - 从 `CriticFeedback` 提炼教训文本。
  - `classify_industry` 关键词命中与 fallback。
  - `min_recurrence` 阈值过滤。
  - 降级路径：mem0 抛错时 `recall_*` 返回 `""`、`remember_*` 不抛。
  - `ContextCompressor.build_history`：未超阈值不压缩；超阈值保留最近 K 轮原文；增量游标推进。
- **集成 smoke（真 mem0 + Milvus，标记 slow/可选，比照现有 eval smoke 待遇）**：
  - 偏好层、方法规范层各跑一次 `add → search` 往返。
- **演示脚本** `backend/app/scripts/demo_memory.py`：
  - 同一行业连跑两次研究，打印第二次 Planner 召回到的教训 + 偏好，展示"系统越用越会做研究"的自我改进闭环。

## 九、验收标准

1. DeepResearch 第二次同行业研究时，Planner prompt 中可见召回的方法规范/偏好（日志或事件可观测）。
2. Chat 多轮对话超阈值后，history 段被压缩，且最近 K 轮逐字保留，prompt token 受控。
3. mem0 / Milvus 不可用时，研究与对话流程均正常完成（仅无记忆增强）。
4. `long_term_memories` 表与旧 `memory_service` 完全移除，`memory_router` 经 mem0 正常列出记忆。
5. 单元测试全绿；集成 smoke 在有外部服务时通过。
